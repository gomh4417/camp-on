# 모바일 그룹 사용 흐름

1. 모바일 웹에서 새 그룹 만들기: 닉네임, 차량명, 목적지를 입력한다. 배터리는 선택 입력(0~100%). 모르면 빈칸.
2. 설정에서 초대 링크를 공유한다. 다른 휴대폰은 닉네임·차량명을 입력하고 연결한다. 고정 CAR A/B/C는 없으며 실제 참여한 차량만 추가된다(최대 30대).
3. 차량 앱의 채워진 파란색 '그룹 연결' 버튼에서 HTTPS 원점 주소, 초대 코드, 대화에 표시할 이름을 입력한다. 차량 화면 연결 자체로 가상의 차량이 추가되지 않는다.
4. 차량 화면은 앱 재실행 시 연결 전 상태로 시작한다. '그룹 연결 관리'에서 등록 차량을 이 화면에 연결하면 해당 차량의 도착 상태를 확인할 수 있다.
5. 각 참여자는 설정의 '내 이동 상태'에서 출발 대기/이동 중/잠시 정차/도착을 직접 공유한다. 연결 성공만으로 출발·도착 처리하지 않는다.
6. 대화에 소식을 남기면 차량 그룹 브리핑에 표시된다. 공동 To-do 담당자는 등록된 닉네임·차량으로 선택한다.

배터리·차량 정보는 참여자 직접 입력값과 입력 시각으로 표시한다. 실시간 센서값이 아니며, 미입력은 미상으로 남긴다. 그룹 일정은 생성자만 변경 가능하다. 연결 해제와 브라우저 로그아웃은 해당 화면의 연결을 종료하며 기존 공동 기록은 보존한다. 다시 새로 참여하면 새 차량이 만들어지므로 기존 참여자는 같은 브라우저의 저장된 세션을 사용한다.

## 실행·배포

프로젝트 루트에서 별도 터미널 두 개:
```powershell
node services/group-sync/companion.mjs
& 'C:/Program Files (x86)/cloudflared/cloudflared.exe' tunnel --url http://127.0.0.1:8788 --no-autoupdate
```

터널의 HTTPS 주소를 연다. PC·서버·터널이 켜져 있어야 한다. 터널 재실행 시 주소가 바뀔 수 있다. 데이터는 Git에서 제외된 services/group-sync/data/companion.json에 저장된다. 서버는 세션 토큰의 해시를 보관한다.

Vercel 정식 배포는 아직 미완료다. mobile 폴더의 vercel.json API rewrite 원점을 실행 중인 백엔드로 지정하고 인증 후 배포해야 한다.

## 검증

Android build/unit 16개/lint 통과. 차량 실행 화면에서 '그룹 연결 전', 출발 전 문구, 채워진 연결 버튼 확인.
npm test 3개: 동적 참여·4대 이상 추가·잘못된 배터리 거절·미입력 유지·화면 연결 시 차량 증가 없음·등록 재시도 중복 방지·발신자 위조 차단·그룹 격리·재시작 보존·모바일 템플릿 렌더링.
출발일/도착 목표는 최소 폭 제한을 제거하고 420px 이하에서 세로 배치. 실제 휴대폰 브라우저 픽셀·키보드 검증은 미실시.
