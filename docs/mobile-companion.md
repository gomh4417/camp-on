# 실제 참여 기반 그룹 흐름

1. Running Device의 그룹 연결 → 새 그룹 만들기에서 대표가 숫자 4자리 초대 코드와 내 닉네임·차량명을 입력한다. 내 차량 1대로 시작한다. 휴대폰은 초대 코드로 참여에서 같은 코드를 입력한다. 차량 앱에서도 코드로 참여를 선택할 수 있다. 영문·공백·3자리·5자리는 허용하지 않으며 0427·0000처럼 앞자리 0을 유지한다. 이미 사용 중인 코드는 새 그룹에 중복 지정할 수 없고 다른 코드를 입력하도록 안내한다. 같은 생성 요청을 재시도해도 차량이 늘어나지 않는다.

   이전 긴 코드를 가진 그룹의 저장 데이터와 로그인 토큰은 보존한다. 새 참여는 4자리 코드만 지원하므로 새 초대가 필요하면 대표가 4자리 코드로 새 그룹을 만든다.
2. '그룹에 참여했어요 · 1대'를 확인한다. 그룹 연결 관리에서 초대 코드를 확인해 휴대폰에 전달한다.
3. 휴대폰에서 초대 코드·닉네임·차량명을 입력해 참여해야 차량이 추가된다. 미리 만든 B/C, 위치, 메시지, 할 일은 없다.
4. 연결 성공은 이동 시작이 아니다. 그룹 이동 상태는 참여자의 명시적 공유값이며 실측 위치가 없으면 지도에 차량을 표시하지 않는다.
5. 배터리·소비량은 출처에 따라 구분한다. 차량 옵션 제어/관측은 Pleos SDK만 사용하며 가짜 제어 모드와 이동 시연 진입점을 제거했다. 배터리 계획은 SDK SOC/입력 용량·전비·소비 가정을 사용한 추정이며, 미상 관측은 그대로 미상이다.

## 시연 데이터 격리

이전 companion.json은 삭제하지 않고 보존한다. 실제 서비스는 companion-live.json을 사용하므로 이전 테스트 참여자·대화가 나타나지 않는다. 이전 초대 코드·토큰은 새 저장소에서 사용할 수 없다. Android 그룹 연결 설정도 별도 membership 저장소로 분리했다. 사용자 입력 없이 새 참여자나 메시지를 만들지 않는다.

테스트는 임시 저장소에서만 가짜 참여자를 생성한다. verify-live.mjs는 상태 확인 GET만 수행한다. npm start는 실제 참여 서버를 시작한다. 기존 server.mjs는 회귀 테스트용이며 앱 기본 주소는 해당 서버(8787)를 사용하지 않는다.

## 현재 모바일 접속 주소

[모바일 웹 열기](https://corrected-bugs-highlights-scheduled.trycloudflare.com/)

2026-11-14 확인: 위 주소의 /api/health는 HTTP 200, {"ok":true}.
이전 winning-luxury-sustained-repeat.trycloudflare.com 주소는 DNS에서 더 이상 조회되지 않는다.
차량 앱의 서버 주소는 http://10.0.2.2:8788 그대로 사용한다.

이 주소는 영구 배포 주소가 아닌 실행 중인 PC의 임시 터널이다. 터널을 재생성하면 새 주소를 공유해야 한다.
[Cloudflare 공식 안내](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/): 프로세스 종료 시 URL이 중단되고 새 터널은 다른 호스트명을 받는다.

## 실행

```powershell
node services/group-sync/companion.mjs
& 'C:/Program Files (x86)/cloudflared/cloudflared.exe' tunnel --url http://127.0.0.1:8788 --no-autoupdate
```

차량 앱 기본 주소는 에뮬레이터용 http://10.0.2.2:8788. 휴대폰은 터널 HTTPS 주소를 사용한다. 서버·PC·터널이 켜져 있어야 한다. 영구 호스팅/Vercel 배포는 미완료. 데이터·토큰은 Git에 올리지 않는다.

## 검증

새 그룹 차량 1대, 빈 대화·할 일, 실제 가입 시 증가, 중복 가입 방지, 서버 재시작 보존, 그룹 격리, 권한·배터리 입력 검증을 임시 저장소에서 수행한다. 실제 휴대폰 키보드/픽셀 검증과 실제 차량 하드웨어 전체 동작은 별도 확인이 필요하다.
