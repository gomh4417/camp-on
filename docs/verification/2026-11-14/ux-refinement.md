# 함께 이동 복원·캠핑 UX 수정

## 수정과 원인

- 비활성 캠핑 세션의 첫 화면을 기존 함께 이동으로 복원했다. 그룹 연결, 지도, 참여 차량, 메모·브리핑, 공동 할 일 흐름을 그대로 사용한다. 캠핑 준비 화면으로 이동해도 그룹의 실제 도착 상태나 차량 설정은 바뀌지 않는다. 진행 중인 캠핑은 기존 세션을 유지한다.
- 실제 실행 기기의 종료 시각이 **2026-11-07 16:09**로 저장되어 있었다. 지난 종료 시각을 알려 주고, 선택 화면에서는 현재부터 8시간 뒤를 초안으로 제안한다. '선택 적용' 전에는 저장하지 않는다.
- 배경 SDK 조회 중이라는 이유만으로 캠핑 시작·모드 적용을 비활성화하던 조건을 제거했다. 작업 mutex로 순서를 보장하고 실행 직전 최신 P단·조작 허용·관측 상태를 다시 검사한다. 종료 시각·연결·주차 제한 사유를 화면에 표시한다. 스크롤 여부로 차량 제한을 우회하지 않는다.
- 고정 1600×900 레터박스를 제거하고 실제 inset-safe 높이를 사용한다. 네 제어 영역은 동일 weight, 모드명은 전체 이름과 가운데 정렬, 휴식은 안락의자·취침은 침대 아이콘이다.
- 닫기 영역은 88×72, 아이콘은 40 디자인 dp로 확대했다. 모드·좌석·차량 상세의 수직 간격은 8~10dp 이상으로 정리했다.
- 조명은 OFF / ON · 밝기 / AUTO / 상태 확인 필요로 구분한다. OFF·AUTO에는 밝기 %를 표시하지 않는다.
- '계획 후 남는 전력'은 현재 전력 − 귀가 − 예비 − 예상 사용량이다. 게이지 아래 각 kWh를 표시하며, 지난 종료 시각으로 계산한 여유를 정상 계획처럼 보여 주지 않는다.
- 등록된 인덕션은 미등록 제안에서 제거한다. 등록 카드에서 수정·삭제한다.
- 날짜·시각 선택은 Figma 색상·필드·버튼을 활용한 앱 내부 달력과 시·분 조절 화면이다. 플랫폼 날짜/시간 대화상자를 사용하지 않는다. 적용 후 원래 시작/모드 화면으로 복귀한다.
- '현재 차량 설정을 저장합니다'로 수정하고 요청한 미리보기 설명 문장을 제거했다.

## 10가지 검수

1. 함께 이동 기본 진입, 연결 전 0대 표시, 캠핑 준비 이동: 계측 및 실제 기기 화면 확인.
2. 기존 그룹 프로토콜·4자리 초대·참여자·메모·할 일 동기화: 서버/클라이언트 회귀 테스트 통과. 운영 그룹에 테스트 참가자를 만들지 않음.
3. 앱 전체 높이 활용 및 시스템 영역 보존: 실제 app bounds 1682×1210 사용, 상하 레터박스 제거.
4. 간격·닫기 크기·모드 정렬·제어 영역 동일 너비: 캡처 육안 및 Compose 너비 assertion 통과.
5. 날짜/시간 선택·만료 날짜 차단·적용 후 복귀: Compose 흐름 테스트 통과.
6. 캠핑 시작 시 저장만 수행, 명시적 모드 적용 때만 차량 요청: 테스트 VehicleSource write count 확인.
7. 배경 조회 중 버튼 활성, 주차 불가 시 제어 차단: 세션 테스트 통과.
8. 조명 OFF/ON/AUTO/미상과 kWh 의미: 표시 helper assertion 및 화면 확인.
9. 인덕션 중복 제안 제거·장비 수정/삭제·계획 저장: 기존 CRUD 및 단일 카드 assertion 통과.
10. 재시작·부분 실패·중복 명령·복원: 세션 회귀 테스트 통과. 실제 SDK 전체 하드웨어 재검증으로 오해하지 않도록 아래 범위를 구분함.

## 검증 결과와 범위

- Gradle assembleDebug / assembleDebugAndroidTest 성공, JVM 19개 통과.
- FigmaScreensTest + CampUxTest + CampSessionTest: 총 12개 통과. 별도 시각 fixture로 46개 화면 캡처·검토.
- Node 회귀 테스트 7개 통과: 3개 클라이언트 그룹·할 일·재시작, 지도 시연, 모바일 등록, GIF.
- 공개 HTTPS 모바일 페이지 390px 폭·폰트·정지 이미지·GIF timing 확인.
- 실제 Pleos 실행 화면에서 기본 함께 이동, 원래 시스템 차량, 지도 로딩, SDK 배터리·온도·P단 수신을 확인했다.
- 실제 휴대폰 2대의 동시 조작과 실차는 이번에 검증하지 않았다. SDK 쓰기 API는 변경하지 않았다. 이전 SDK 시험의 시트 등받이 4개 미반영 한계는 그대로이며 전체 SDK 성공으로 표시하지 않는다.
- Graphify local AST 갱신. Kotlin 2개 파일 부분 추출 경고가 있어 소스·Kotlin 빌드·테스트를 판정 근거로 사용했다.
