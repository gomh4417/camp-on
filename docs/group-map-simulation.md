# 그룹 이동 → 캠핑 준비

1. 그룹 연결에서 대표는 숫자 4자리 코드·닉네임·차량명으로 그룹을 생성한다. 동행은 코드로 참여한다. 서버 주소는 앱 설정으로 처리하고 UI에는 노출하지 않는다.
2. 지도에서 출발지와 목적지를 선택한다. 지도 지점을 누르거나 지도 중심을 선택할 수 있다.
3. 파란색 설정 완료 버튼으로 도로 경로를 조회한다. 경로가 준비되고 그룹 연결이 유효해야 함께 출발하기 버튼이 활성화된다.
4. 함께 출발하기를 누르면 실제 등록된 참여자 프로필 핀이 선택 경로를 따라 이동한다. 중복 누름은 진행을 초기화하지 않는다.
5. 마지막 참여자의 핀이 도착하면 캠핑 준비 화면으로 전환한다. 캠핑 세션 시작과 SDK 제어는 이 전환으로 실행되지 않는다.
6. 그룹 메시지 또는 브리핑 카드에서 전체 메시지·휴게소 메모·구매 요청을 확인한다. 메시지 화면과 지도 확대를 오가도 경로 및 진행 상태가 유지된다.
7. 캠핑 종료·복원이 완료되면 처음의 그룹 이동 화면으로 돌아가 저장한 이동 경로를 역순으로 재생한다. 마지막 핀이 출발지에 도착하면 그 화면에 머문다. 복원 미완료 항목이 있으면 기존 확인 화면을 유지한다.

프로필은 닉네임의 첫 유니코드 문자를 사용한다. 모바일 가입 미리보기, 차량 목록, 전체 메시지 및 지도 핀에 같은 규칙을 적용한다. 사진 업로드나 별도 이미지 저장은 필요하지 않다.

연결창은 #FEFEFE 배경과 약한 그림자, 파란 새 그룹 만들기 버튼, 파란 텍스트 코드로 참여 버튼을 사용한다. 이동 화면에는 기어 표시를 하지 않으며 캠핑 화면에서만 SDK 관측값을 표시한다.

## 구현 경계

OSM 지도, Leaflet 1.9.4, OSRM route API를 재사용한다. 약 1분으로 압축된 로컬 경로 애니메이션이다. 실제 GPS 추적이나 ETA가 아니며 서버 목적지·차량 위치·도착 상태·기어·SDK 제어 권한을 변경하지 않는다. UI의 시연 전용 제어/문구는 제거했다.

관측 위치 레이어와 경로 애니메이션 레이어는 분리되어 있다. 참여자가 바뀌거나 연결이 끊기면 경로 준비를 무효화한다. 경로 요청은 취소 및 12초 제한을 처리하고 실패 시 직선 경로로 대체하지 않는다. 화면 숨김/메시지 열기 중에는 진행을 멈추고 돌아오면 이어진다. 진행 중 경로는 프로세스 재시작 시 다시 설정한다. 캠핑장 도착이 완료된 경로는 로컬에 저장하며 그룹 재연결 후 귀가에 재사용한다. 그룹을 바꾸거나 연결을 해제하면 저장된 경로를 삭제한다. 귀가 경로가 없거나 그룹 연결이 유효하지 않으면 안내를 표시하고 임의 경로를 생성하지 않는다.

앱과 모바일의 정지 화면 전환 버튼은 제거했다. 시스템 동작 줄이기 설정에서는 캠핑 장면과 핀 이동 애니메이션을 생략하고 도착 시점을 정적으로 표시한다. 공용 지도/경로 서버의 가용성은 외부 의존성이다.

## 검증

- npm test: 초대·공동 메시지·할 일·재시작, 준비/출발 분리, 중복 출발, 마지막 참여자 도착, 지도 재생성, 참여자 변경, 동작 줄이기, 지연 응답 폐기, 경로 실패.
- verify-group-departure.mjs: 운영 데이터와 분리된 18789 서버 및 임시 저장소에서 Android GroupDepartureTest, KeyboardStabilityTest, CampUxTest 실행.
- GroupDepartureTest는 3명 가입과 휴게소 메모의 실제 HTTP 송수신, 전체 메시지 UI, WebView ↔ Compose의 출발/도착 전환을 검증한다. 경로는 결정적 테스트 fixture로 주입하며 실제 도로 조회는 별도 확인 대상이다.
